Most services run with Nixpacks (or a Dockerfile) and a single replica. These are the knobs you change when that is not enough.

## Build and deploy

Open the service sheet → **Settings**.

**Build**

- If a `Dockerfile` is in the service root, it wins. Otherwise Nixpacks detects the runtime.
- Override install / build / start when detection is wrong.
- Monorepos set a **root directory** so one repo can back several services.

**Deploy**

- [Replicas](/scaling/horizontal/) for more than one instance.
- [Autoscaling](/scaling/autoscaling/) from CPU or memory.
- [Cron](/deploy/cron-jobs/) if the process should run on a schedule and exit.
- [Health checks](/storage/health-checks/) so traffic waits for a ready revision.
- [Staged changes](/deploy/staged-changes/) apply a batch of canvas edits at once.

There is no serverless sleep product on this control plane. Services stay up unless you scale them to zero or delete them.

## Networking

- **Private** — service name DNS inside the environment. See [private networking](/networking/private-networking/).
- **Public** — generate a `*.stackblaze.app` domain or attach your own. See [public networking](/networking/custom-domains/).
- TLS is issued after DNS checks out. See [SSL](/networking/ssl/).

## Environments

Production is created with the project. Add more environments for staging. Pull requests can get a [preview environment](/cicd/pr-previews/) that does not share production data.

## Observability

Logs, metrics, and traces are [Coroot](/operations/observability/), opened from the service. Search logs from the dashboard or MCP (`search_logs`).

## Config as code

`stackblaze.yaml` can describe the project. Plan and apply when IaC is enabled. See [config as code](/blueprint/).

## Automation

Automate with the [CLI](/cli/), the [REST API](/reference/api/), or [MCP](/agents/).
