---
title: Production readiness checklist
description: What to confirm before a StackBlaze project carries production traffic.
---

Use this as a pre-launch pass. Every item maps to a feature that exists here.

## Performance and reliability

- **Region** — a project runs in the region picked at create time. Keep chatty services and their databases in that project.
- **Private networking** — app-to-database and app-to-app traffic uses [service names](/networking/private-networking/), not public URLs.
- **Replicas** — run at least two instances on public HTTP if you cannot afford a single-instance blip (Pro allows 3 per service, Business 10). See [horizontal scaling](/scaling/horizontal/).
- **Sleep mode** — leave it off on services that must answer at once; a sleeping service has to wake first.
- **Health checks** — set a path so rolling deploys wait for ready. See [health checks](/storage/health-checks/).
- **Database topology** — use high availability for production data stores (Pro and Business plans). See [databases](/databases/).

## Observability

- Open [Coroot](/operations/observability/) from the service and confirm logs and metrics.
- Prefer `search_logs` over a raw tail in MCP.

## Quality

- Keep a non-production [environment](/deploy/environments/) for staging.
- Turn on [PR previews](/cicd/pr-previews/) if you want a live canvas per pull request (Pro and Business plans).
- Keep topology in [stackblaze.yaml](/blueprint/) if you want git-reviewed infra.
- Know how to [roll back](/cicd/rollbacks/) a revision.

## Security

- Secrets in [variables](/security/env-vars/), not in git.
- [2FA](/security/two-factor-auth/) on every account.
- **Inbound IP rules** in the service's **Advanced networking** settings if an app should only accept certain source IPs.
- Do not expose databases on the public internet.

## Recovery

- Turn on [backups](/databases/backups/) for stateful databases. Nothing schedules them by default, and the Free Trial has none.
- Know [PITR](/databases/pitr/) for Postgres if you need point-in-time restore.
- [Volumes](/storage/persistent-disks/) are not a backup strategy by themselves.
