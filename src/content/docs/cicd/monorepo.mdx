StackBlaze supports monorepos out of the box. Multiple services can point to the same GitHub repository, each with its own build path, build command, build filters, and deploy history. Turborepo, Nx, pnpm workspaces, and plain npm/yarn monorepos all work.

Build filters ensure that only the relevant services rebuild when you push a change. A commit that only touches `apps/web` won't trigger a build for `apps/api`, saving build time and preventing unnecessary churn.

<Diagram file="monorepo-path-filters.svg" alt="One Git repository fans out to web-frontend, web-api, and bg-worker. Path filters queue a build only for services whose patterns match the changed files. A shared repo is not a shared build." />

## Example monorepo structure

```text title="acmecorp/monorepo"
# Repository root
acmecorp/
├── apps/
│   ├── web/          # Next.js frontend, StackBlaze: web-frontend
│   ├── api/          # Express API, StackBlaze: web-api
│   └── worker/       # Private service, StackBlaze: worker
├── packages/
│   ├── ui/           # Shared component library
│   └── utils/        # Shared utilities
├── turbo.json
├── package.json
└── pnpm-workspace.yaml
```

## Per-service settings

| Service | Build path | Build command | Build filter (`includedPaths`) |
| --- | --- | --- | --- |
| `web-frontend` | `apps/web` | `turbo run build --filter=web` | `apps/web/**`, `packages/**` |
| `web-api` | `apps/api` | `turbo run build --filter=api` | `apps/api/**`, `packages/**` |
| `bg-worker` | `apps/worker` | `turbo run build --filter=worker` | `apps/worker/**`, `packages/**` |

## Turborepo `turbo.json`

```json title="turbo.json"
{
  "$schema": "https://turbo.build/schema.json",
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**"]
    }
  }
}
```

```text
# Build command per service:
# turbo run build --filter=web   (builds web + its deps)
# turbo run build --filter=api   (builds api + its deps)
```

:::note[How it works]
- **Separate builds**: each service gets its own build, even when services share a repository. A push that touches several services builds each of them.
- **Build path**: the build runs with your build path as its context. The Dockerfile path and build path are both relative to the repo root.
- **Build filters**: StackBlaze compares the changed files in the push with each service's filters. A service only builds when at least one changed file counts. With no filters, a service with a build path such as `apps/web` watches `apps/web/**`. When GitHub does not report the changed files, every service builds.
:::

## Step by step

1. **Add the repository**

   Click **+ Service → GitHub repository** and pick the repo. StackBlaze scans it and offers one service per app folder it can build (a folder with a Dockerfile or a language manifest such as `package.json`). You can also add each service yourself; they can all point to the same repository. Each has its own variables, settings, and deploy history.

2. **Set the build path per service**

   In the service's **Settings**, set **Build path** to the app's folder, for example `apps/web`. Paths are relative to the repo root. With **Docker** as the build method, pick the **Dockerfile** too (for example `apps/web/Dockerfile`).

3. **Configure build filters**

   By default a service only rebuilds for changes under its build path. If it also depends on shared code, list the paths in `stackblaze.yaml`:

   ```yaml title="stackblaze.yaml"
   services:
     - name: web-frontend
       rootDir: apps/web
       buildFilter:
         includedPaths: ["apps/web/**", "packages/**"]
         ignoredPaths: ["**/*.md"]
   ```

   Patterns are gitignore-style globs. `ignoredPaths` wins over `includedPaths`.

4. **Set the build command**

   Leave **Build command** blank to use the framework default, or set one for your monorepo tool. For Turborepo: `turbo run build --filter=web`. For Nx: `nx build web`. For pnpm workspaces: `pnpm --filter web run build`.

5. **Set the start command**

   Set **Start command** to run your app, for example `node dist/index.js`. Leave it blank to use the framework default.
