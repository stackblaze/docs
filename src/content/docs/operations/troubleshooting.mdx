A checklist for the issues support sees most often. Start here before opening a ticket.

## Deployment failures

Open the service's **Deployment** tab, pick **Inspect Deployment** on the failed row, and find the first failing step. Most failures fall into one of these buckets:

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Build exits 1 immediately | Wrong build path or missing lockfile | Set **Build path** in Settings; commit package-lock.json or yarn.lock |
| Module not found at runtime | Dev dependency used in production | Move the package to dependencies or set NODE_ENV=production in build |
| Container exits after start | Process binds to localhost only | Listen on 0.0.0.0 and use process.env.PORT |
| Deploy never goes live | Health check never passes | See Health checks below |
| Deploy stops before rollout | Pre-deploy command failed | Check its output in the deploy's logs; the current version keeps running |
| Build refused | Plan's concurrent build limit reached | Wait for a running build to finish |
| Build stopped after a long time | Plan's build timeout reached | Speed up the build, or upgrade the plan |

## Health checks

With health checks on, a new version only takes traffic once your health path (default `/`) answers successfully. A common mistake is checking a dependency that is not ready on cold start.

:::tip
Temporarily point the health path at a static `/health` that returns 200 with no DB checks. If deploys succeed, fix the dependency timeout, or raise **Startup** under **Settings → Health checks** (90 s by default).
:::

See [Health checks](/storage/health-checks/) and [Zero-downtime deploys](/scaling/zero-downtime/) for probe configuration.

## Environment variables

Variable edits are [staged](/deploy/staged-changes/): they apply after **Commit N changes** → **Deploy**. If the app still sees old values, confirm you deployed the change and edited the correct **environment** (production vs a preview).

### DATABASE_URL missing

Connect the database to the service on the canvas. StackBlaze injects its connection variables (for PostgreSQL: `DATABASE_URL`, `PGHOST`, `PGUSER`, and friends). Do not paste a localhost URL from your laptop.

## Custom domains and SSL

DNS can take up to 48 hours to propagate. Check that both the `TXT` and `CNAME` records match the values in **Settings → Domains → Configure DNS**, then click **Verify now**. See [Public networking](/networking/custom-domains/#troubleshooting).

## Database connection errors

Managed databases are reachable on the private network from services in the same environment. Connection refused usually means the service and database are in different environments or projects, or the app is using a URL from a local `.env`.

## Out of memory (OOM)

Check **Metrics → Memory**. If memory hits the limit and the instance restarts, reduce in-process cache size, run fewer instances (each gets a larger share of the plan's size), or upgrade the plan. Node apps should pass `--max-old-space-size` below the container limit.

See [Memory & CPU limits](/scaling/limits/).
