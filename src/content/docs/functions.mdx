title: Functions
description: One TypeScript file run on Bun, with no build. It sleeps when idle, or runs on a schedule.
---

A **function** is a service on the project canvas whose program is **one TypeScript file**. StackBlaze runs it on a stock Bun image. There is no build step and no image to push.

A function works in one of two ways:

- **No schedule** — a web service with its own URL. It sleeps after 15 minutes without a request. The next request wakes it; that request waits for the function and gets its answer.
- **With a schedule** — the same file runs on a cron schedule (UTC). It has no URL and serves no HTTP.

Use an always-on [service](/build-deploy/apps/) for a long-running API or anything you build from a repo.

## Create a function

1. On the canvas, click **+ Service** and pick **Function** ("One TypeScript file, no build").
2. Edit the file on the **Code** tab. A new function starts with a small `Bun.serve` example.
3. Click **Deploy**.

The **Function** row only shows when Functions is turned on for your platform and allowed on your plan. If it is off, creating a function is refused; existing functions can still be edited and deleted.

## The code

- The file is `index.ts`, run with `bun run`. Import npm packages directly; Bun installs them on first use.
- Listen on `process.env.PORT` (default `8080`).
- The file can be at most **96 KB**.
- Set [variables](/security/env-vars/) on the **Variables** tab like any other service.

```ts title="index.ts"
Bun.serve({
  port: Number(process.env.PORT ?? 8080),
  fetch(req) {
    return new Response("Hello from your function");
  },
});
```

The **Code** tab shows the function's URL when it has one. A sleeping function shows **Sleeping** on the canvas.

## Schedule

Open **Settings → Schedule** and pick **No schedule**, **Every 5 minutes**, **Every hour**, **Every day**, **Every week**, or **Custom** (a five-field cron expression, for example `0 2 * * *`). Times are UTC.

A scheduled function has no **Domains** section and no URL. Each run shows in its logs.

## Settings

StackBlaze owns a function's image, start command, replicas, and sleep. You set the code, the schedule, the domains (web functions only), and the variables. A function cannot be turned into a regular service, or a regular service into a function.

## Config as code

In [`stackblaze.yaml`](/blueprint/), use `type: function` with the source inline in `code`. Add `schedule` for a scheduled function.

```yaml title="stackblaze.yaml"
services:
  - name: hello
    type: function
    code: |
      Bun.serve({
        port: Number(process.env.PORT ?? 8080),
        fetch: () => new Response("hi"),
      });
```

Build fields (`runtime`, `rootDir`, `image`, `startCommand`, scaling, disks, auto-deploy) are not allowed on a function.
