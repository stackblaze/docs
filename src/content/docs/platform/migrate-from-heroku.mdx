---

A Heroku app maps onto a StackBlaze **project**. Each process type becomes a **service** on the project canvas, config vars become **variables**, and add-ons become databases on the same canvas. Services stay up; there is no sleeping on inactivity.

## Step by step

<Steps>

1. **Export your Heroku config vars**

   Print them in `KEY=value` form:

   ```bash
   heroku config --shell -a my-app > heroku.env
   ```

   Review the file. Drop values that point at Heroku add-ons (`DATABASE_URL`, `REDIS_URL`): the new databases provide their own.

2. **Create the project from your GitHub repo**

   In the dashboard, create a project and choose your GitHub repository and branch. Install the StackBlaze GitHub App if prompted. No changes to your repository are required. See [GitHub](/deploy/github/).

3. **Check what StackBlaze read from the Procfile**

   StackBlaze reads the `Procfile` when it inspects the repo:

   - `web:` becomes the service's start command, and the service takes public HTTP traffic.
   - With no `web:` line, `worker:` becomes the start command of a service with no public domain.
   - `release:` becomes the service's **Pre-deploy** command. It runs before the new version starts; if it fails, the current version stays live.

   ```text title="Procfile"
   web: node dist/server.js
   worker: node dist/worker.js
   release: node dist/migrate.js
   ```

   A service runs one process. If you have both `web:` and `worker:`, add a second service from the same repo with **+ Service** and set its start command to the worker command.

4. **Pick the build method**

   If the repo has a `Dockerfile`, it is used. Otherwise the default build method auto-detects the runtime. To build with Cloud Native Buildpacks, as Heroku does, choose **Buildpacks** as the build method in the service's build settings.

5. **Add the databases**

   Add Postgres and Redis to the same canvas with **+ Service**. They run on the environment's private network. Attach each one to the services that use it, so the connection details are injected as variables. See [Databases](/databases/).

6. **Paste your config vars**

   Open the service → **Variables** → **Raw editor** and paste the contents of `heroku.env`. See [Variables](/security/env-vars/).

7. **Move Heroku Scheduler jobs**

   Each scheduled job becomes a [cron job](/deploy/cron-jobs/) service with the same command and schedule.

8. **Deploy, test, then move the domain**

   Commit the staged changes to deploy. Test on a staging [environment](/deploy/environments/) first if you have one. Then add your [custom domain](/networking/custom-domains/) under the service's **Settings → Domains**. TLS is issued automatically.

</Steps>

## Heroku → StackBlaze

| Heroku | StackBlaze |
| --- | --- |
| App | Project |
| `web` process | Service with public HTTP |
| `worker` process | Service with no public domain |
| `release` phase | Pre-deploy command on the service |
| Heroku Postgres | Postgres on the canvas |
| Heroku Redis | Redis (Valkey) on the canvas |
| Heroku Scheduler | Cron job service |
| `heroku config:set` | Service → **Variables** |
| `heroku ps:scale web=2` | [Horizontal scaling](/scaling/horizontal/) |
| `heroku releases` | Service → **Deployment** (history and rollbacks) |
| Pipelines and review apps | [Environments](/deploy/environments/) and [PR previews](/cicd/pr-previews/) |
