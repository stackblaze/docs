---
title: stackblaze addons
description: "List add-on types and attach or detach add-ons on an app."
---

Add-ons are managed services (for example PostgreSQL or Redis) attached to an app. Alias: `addon`.

## Usage

```text
stackblaze addons list [--attached]
stackblaze addons add [kind] [--wait] [--timeout <seconds>]
stackblaze addons delete [kind] [--instance <name>] [-y]
stackblaze addons import <file> [addon] [--instance <name>] [--clean] [--stop-on-error] [-y]
```

| Subcommand | Description |
| --- | --- |
| `list` | Add-on types you can attach. With `--attached`, the add-ons on the app in scope and their state |
| `add <kind>` | Attach an add-on of this kind to the app. Fails if one of that kind is already attached |
| `delete <kind>` | Detach an add-on; asks for confirmation unless `-y` |
| `import <file> [addon]` | Load a PostgreSQL or MySQL / MariaDB dump made elsewhere into a database add-on (see [below](#import-a-dump)) |

| Flag | Applies to | Description |
| --- | --- | --- |
| `--attached` | `list` | List the app's attached add-ons |
| `--wait` | `add` | Wait until the app and the add-on are running |
| `--timeout <seconds>` | `add` | Maximum `--wait` time (default `600`; a new database cluster can take several minutes) |
| `--instance <name>` | `delete`, `import` | Which instance, when several match |
| `--kind <name>` | `add`, `delete` | Same as the positional `[kind]`; passing both with different values is an error |
| `--clean` | `import` | PostgreSQL archives: drop the objects the dump recreates before loading them |
| `--stop-on-error` | `import` | Stop at the first error instead of carrying on |
| `-y, --yes` | `delete`, `import` | Skip the confirmation |

Every subcommand accepts the [scope and output flags](/cli/#scope-and-common-flags): `-p, --pipeline`, `--phase`, `-a, --app`, `--token`, `--api-url`, `-o, --output`, `--json`.

## Examples

```bash
stackblaze addons list
stackblaze addons add <kind> --wait
stackblaze addons add <kind> --wait --timeout 900 --json | jq .wait.ready
stackblaze addons list --attached -o json
```

With `--wait --json`, stdout carries one JSON document: the result with the readiness check under `wait`. A wait that ends without the app and add-on running exits `1`.

Use `addons list` for the exact kind names. To open a database shell, see [`stackblaze connect`](/cli/connect/).

## Import a dump

`addons import` loads a dump made on another system into a PostgreSQL or MySQL / MariaDB add-on (CLI 1.1.9 or newer). `[addon]` is the instance name or its type (`postgres`, `mysql`); left out, the app's only database add-on is used.

```bash
stackblaze addons import backup.dump                        # pg_dump -Fc archive -> pg_restore
stackblaze addons import dump.sql                           # plain SQL -> psql or mysql
stackblaze addons import backup.dump postgres --clean -y    # re-run into a database that has the tables
stackblaze addons import shop.sql.gz --instance orders      # gzipped dumps work too
```

- The format is read from the file's contents: `pg_dump` custom, tar and directory archives go through `pg_restore --no-owner --no-acl`; plain SQL goes through `psql` or `mysql`.
- The client runs on your machine through the same private tunnel as [`connect --local`](/cli/connect/#how-it-works), with the same access rules and limits. `psql`, `pg_restore` or `mysql` must be installed.
- The dump goes into the add-on's existing database, so the command asks first (`-y` skips it).
- Any error exits `1` and the database may be partly loaded; a refused tunnel exits `3`.

For the full walkthrough, see [Import a database dump](/databases/import-dump/).
