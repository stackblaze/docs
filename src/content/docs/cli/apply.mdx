---
title: stackblaze apply
description: "Create or update pipelines and apps from manifest files."
---

Creates or updates every pipeline and app declared in the manifests (pipelines first). It never deletes; use [`destroy`](/cli/destroy/) for that.

## Usage

```text
stackblaze apply <path> [--continue-on-error] [-o text|json]
```

| Flag | Description |
| --- | --- |
| `--continue-on-error` | Keep going after a resource fails (default: stop at the first failure) |

Also accepts `--token`, `--api-url`, `-o, --output` and `--json` (see [common flags](/cli/#scope-and-common-flags)).

The manifest format is the one [`stackblaze export`](/cli/export/) writes: YAML documents of `kind: KuberoPipeline` or `kind: KuberoApp`. App documents need `metadata.pipeline` and `metadata.phase`. A path can be a file or a directory (all `.yaml` / `.yml` files, recursively). This is separate from the `stackblaze.yaml` [config as code](/blueprint/) file.

Infrastructure as Code must be enabled; check with [`stackblaze status`](/cli/status/).

Exits `1` if any resource failed. The JSON result lists each resource with `action`: `created`, `updated` or `failed`.

```bash
stackblaze plan ./stackblaze && stackblaze apply ./stackblaze
```
