---
title: stackblaze files
description: "Browse, download, upload, rename and delete files on an app's volumes."
---

Works on files inside the app's volume mounts, through a running pod. Your platform admin may turn it off.

## Usage

```text
stackblaze files mounts
stackblaze files list [path]
stackblaze files download [path] [--out <file>]
stackblaze files upload <local> --path <path> [--extract]
stackblaze files rename --from <path> --to <path>
stackblaze files delete [path] [-y]
```

| Subcommand | Description |
| --- | --- |
| `mounts` | Volume mount paths you can use |
| `list [path]` | Files under a path. Alias: `ls` |
| `download [path]` | Download a file or directory as a tar archive (default `<basename>.tar`) |
| `upload <local>` | Upload a local file. With a `--path` ending in `/` or `--extract`, a tar archive is extracted there (automatic for `.tar` / `.tgz`) |
| `rename` | Rename or move a file |
| `delete [path]` | Delete a file or directory; asks for confirmation unless `-y` |

| Flag | Description |
| --- | --- |
| `--path <path>` | Absolute path under a mount, e.g. `/data`. `list`, `download` and `delete` also take it positionally |
| `--out <file>` | `download`: local file to write (default `<basename>.tar`) |
| `--pod <name>`, `--container <name>` | Target pod and container (default: the app's primary pod and its `web` container) |

Every subcommand accepts the [scope and output flags](/cli/#scope-and-common-flags): `-p, --project`, `-e, --env`, `-a, --app`, `--token`, `--api-url`, `-o, --output`, `--json`.

`files download` still accepts `-o <file>` as an older spelling of `--out`; `-o json` and `-o text` select the output format as on every other command.

## Examples

```bash
stackblaze files mounts
stackblaze files list /data
stackblaze files download --path /data/uploads --out uploads.tar
stackblaze files upload ./seed.tgz --path /data/
```
