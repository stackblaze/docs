---
title: stackblaze deployments
description: "Show deploy history and roll back to an earlier image or configuration."
---

Alias: `deployment`.

## Usage

```text
stackblaze deployments list [-n <limit>]
stackblaze deployments rollback [deploy-id] [--image-only] [--wait] [--timeout <seconds>] [-y]
```

| Subcommand | Description |
| --- | --- |
| `list` | Deploy history of the app: git builds, image deploys and configuration releases, with status, trigger and ref (commit or image tag) |
| `rollback [deploy-id]` | Roll back to an earlier deploy. Without an ID, the previous successful deploy. Asks for confirmation unless `-y` |

## Options

| Flag | Applies to | Description |
| --- | --- | --- |
| `-n, --limit <n>` | `list` | Maximum entries (server default 100) |
| `--build <name>` | `rollback` | Build name to roll back to (same as the positional ID) |
| `--image-only` | `rollback` | Redeploy only the image tag; keep the current configuration and auto-deploy |
| `--wait` | `rollback` | Wait until the app is running again; exits `1` if it does not become ready |
| `--timeout <seconds>` | `rollback` | Maximum `--wait` time (default `600`) |
| `-y, --yes` | `rollback` | Skip the confirmation |

Every subcommand accepts the [scope and output flags](/cli/#scope-and-common-flags): `-p, --project`, `-e, --env`, `-a, --app`, `--token`, `--api-url`, `-o, --output`, `--json`.

## Examples

```bash
stackblaze deployments list -n 20
stackblaze deployments rollback -y --wait
stackblaze deployments rollback web-1a2b3c -y
stackblaze deployments rollback <deploy-id> -y --wait --json | jq .wait.ready
```

## How it works

`<deploy-id>` is an ID from `stackblaze deployments list`: a history entry's ID or a build name. What a rollback does depends on the entry:

- **Image deploys and builds** come back in full: the entry's image and the configuration it ran with. Auto-deploy turns off, so the next push does not bring the change back; turn it back on in the app's settings once the fix is pushed. Add-ons, volumes, domains and the plan stay as they are. With `--image-only`, only the image tag is redeployed. This works for image apps as well as apps built from source.
- **Configuration releases** (variable and scale changes) roll back the configuration to that revision.

Without an ID, `rollback` picks the newest deploy that succeeded and is not the one running now. The confirmation names the target: `image tag … and the configuration it ran with`, `image tag …` or `configuration revision …`.

With `--wait --json`, stdout carries one JSON document: the rollback result (`deploy`, `kind` `image` or `config`, `tag` or `revisionId`; for image rollbacks `full`, and `autodeploy: false` when it was a full rollback) with the readiness check under `wait`. The exit code is `1` when the app does not come up.
