---
title: stackblaze metrics
description: "Show current CPU and memory usage per pod, or history over a time window."
---

Without `--since`, prints current CPU (millicores) and memory (MiB) for each of the linked app's pods. With `--since`, prints history over the window for all pods combined: a sparkline with now, average and max for CPU, memory, requests and latency.

## Usage

```text
stackblaze metrics [--since <window>] [--watch] [--interval <seconds>] [options]
```

| Flag | Description |
| --- | --- |
| `--since <window>` | History window: `30m`, `1h`, `24h`, `7d` (max `7d`) |
| `-w, --watch` | Refresh the history until Ctrl-C (default window `1h`) |
| `--interval <seconds>` | Seconds between `--watch` refreshes (default `30`) |

Also accepts the [scope and output flags](/cli/#scope-and-common-flags): `-p, --project`, `-e, --env`, `-a, --app`, `--token`, `--api-url`, `-o, --output`, `--json`.

`--json` prints the raw series (timestamps in milliseconds). `--watch --json` prints one JSON document per refresh (NDJSON).

## Examples

```bash
stackblaze metrics
stackblaze metrics --since 24h
stackblaze metrics --since 1h --watch
stackblaze metrics --since 7d --json
```

For analysis, use [`stackblaze diagnose`](/cli/diagnose/).
