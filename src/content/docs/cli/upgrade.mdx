---
title: stackblaze upgrade
description: "Update the CLI binary in place."
---

Downloads the newest CLI build for your platform and replaces the running binary.

## Usage

```text
stackblaze upgrade [--channel stable|dev] [--version <x.y.z>] [--install-path <file>]
```

| Flag | Description |
| --- | --- |
| `--channel <name>` | `stable` (default) or `dev` (prereleases); also `STACKBLAZE_CHANNEL` |
| `--version <tag>` | Install a specific version, e.g. `1.0.0` |
| `--install-path <path>` | Binary to replace (default: the running binary; also `STACKBLAZE_INSTALL_PATH`) |
| `--oras` | Pull from `ghcr.io` with the `oras` tool instead of GitHub Releases |

## Examples

```bash
stackblaze upgrade
stackblaze upgrade --channel dev
stackblaze upgrade --version 1.0.0
```

On Linux and macOS the old binary is kept next to the new one as `stackblaze.bak` (if it can be renamed). On Windows, `upgrade` renames the running `stackblaze.exe` to `stackblaze.old.exe`, moves the new binary into place, and removes the old file on a later start.

A CLI installed with Homebrew is not replaced: `upgrade` stops and tells you to run `brew upgrade stackblaze`. Re-running the [installer](/cli/#install) also upgrades.

Check the version with `stackblaze --version`.
