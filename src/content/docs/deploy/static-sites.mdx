---
title: Static sites
description: Build a frontend and serve the output from a StackBlaze service.
---

There is no separate static-site type on StackBlaze. A static site is a **service** whose container serves your built files over HTTP. StackBlaze gives it a public URL with HTTPS like any other [public service](/deploy/web-services/).

Importing a `render.yaml` static site (`runtime: static`) is skipped for this reason; serve the files from an image instead.

## Option 1: Dockerfile with nginx

Build the site in one stage and serve it with nginx in the next. Choose the **Docker** build method.

```dockerfile title="Dockerfile"
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build          # writes dist/

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 8080
```

```nginx title="nginx.conf"
server {
  listen 8080;
  root /usr/share/nginx/html;

  # Single-page app: send unknown paths to index.html
  location / {
    try_files $uri $uri/ /index.html;
  }

  # Long cache for content-hashed assets
  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
  }
}
```

Set the service port to `8080`. Redirects, rewrites, a custom 404 page, and cache headers all go in `nginx.conf`.

## Option 2: a small Node server

With the **Railpack** build method, set a **Build command** (for example `npm run build`) and a **Start command** that serves the output folder on `$PORT`, for example `npx serve -s dist -l $PORT`.

## Next.js static export

Next.js needs `output: 'export'` in `next.config.js` to produce static files. Without it, Next.js needs a Node.js server: deploy it as a normal service.

```javascript title="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'export',        // enables static export
  trailingSlash: true,
  images: {
    unoptimized: true,     // next/image requires a server; disable for static export
  },
}

module.exports = nextConfig
```

## Environment variables in static builds

The service's [variables](/security/env-vars/) are available to the build. A static bundle has no server, so any value the browser needs must be embedded at build time:

- **Vite**: prefix with `VITE_`, read `import.meta.env.VITE_API_URL`.
- **Create React App**: prefix with `REACT_APP_`, read `process.env.REACT_APP_API_URL`.
- **Next.js**: prefix with `NEXT_PUBLIC_`, read `process.env.NEXT_PUBLIC_API_URL`.

:::caution
Never embed private API keys or secrets in a static build. They become part of the public JavaScript bundle and anyone can read them.
:::

## Custom domains

Attach a custom domain the same way as for any other service. See [Public networking](/networking/custom-domains/).

## CDN cache

When a service is served through the StackBlaze edge, the service's actions menu offers **Clear CDN cache**. To drop the cached copies of a service's pages after a change, use it or `stackblaze cdn purge`. It purges only that service's own hostnames.
