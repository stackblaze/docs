An **environment** is an isolated copy of a project's canvas: the same services and databases, separate runtime and data.

<Diagram file="environments-isolation.svg" alt="Three isolated environments in one project: durable production, a custom staging or QA copy, and a review environment torn down when the pull request closes" />

## Production

Created with the project. This is the live environment. Its services usually deploy your main branch.

## Custom environments

Turn on more environments in **Project settings → General → Environments**: `dev`, `test`, and `stage` sit next to `production`. A newly enabled environment deploys to the same region as your existing ones. Services and databases in each environment have their own [variables](/security/env-vars/) and private network. They do not share volumes or database data with production.

Your plan limits how many environments a project can have.

## Pull-request previews

When preview environments are on for the project, opening a pull request creates a `pr-<number>` environment: a copy of the environment that deploys the PR's target branch. Its databases start empty, so previews do not share production data. The environment is removed when the PR is merged or closed, or after a number of days without a push.

See [PR previews](/cicd/pr-previews/) for branch mapping and teardown.

| Environment | When created | Lifespan |
| --- | --- | --- |
| production | With the project | Until you delete the project |
| dev / test / stage | From project settings | Until you turn it off |
| `pr-<number>` | When a PR opens (if previews are on) | Until the PR closes or the preview expires |

## Switching environments

The canvas is always showing **one** environment. Use the environment switcher in the project header. Staged changes apply only to the environment you are viewing.

## API names

Projects are `pipeline` and environments are `phase` in API paths: `/api/apps/{pipeline}/{phase}/{app}`.
