A **scheduled task** runs a command on a cron schedule. At each tick StackBlaze starts a fresh container, runs the command, and lets it exit. It uses the service's own built image and [variables](/security/env-vars/), unless you give the task its own image.

## Add a scheduled task

Scheduled tasks live on a service:

1. Open the service and go to the **Add-ons** tab, or pick **Add-on → Scheduled tasks** from **+ Service**.
2. Click **Add scheduled task** and fill in:
   - **Name** — for example `nightly-cleanup`.
   - **Schedule** — a five-field cron expression (minute hour day month weekday).
   - **Image** — optional; leave empty to run the service's own image.
   - **Command** — for example `/bin/sh -c 'node report.js'`.
3. Save, then **Commit N changes** → **Deploy** to apply.

Turn on **Schedule-only app** when the service should have no always-on web or worker pods, only the scheduled runs. This is what a cron job is on StackBlaze: a service from a Git repo or Docker image whose only work is its scheduled tasks.

In [`stackblaze.yaml`](/blueprint/), use `type: cron` with `schedule` and `startCommand`.

## How runs work

Each run is isolated. Nothing is shared between runs except what you persist to a database or object storage. The process should exit 0; a non-zero exit marks the run as failed.

## Schedule syntax

StackBlaze uses standard five-field cron expression syntax:

```text
┌─────────── minute       (0–59)
│ ┌───────── hour         (0–23)
│ │ ┌─────── day of month (1–31)
│ │ │ ┌───── month        (1–12)
│ │ │ │ ┌─── day of week  (0–6, Sunday = 0)
│ │ │ │ │
* * * * *
```

### Common schedule examples

| Schedule | Expression | Description |
| --- | --- | --- |
| Every minute | `* * * * *` | Runs every 60 seconds |
| Every hour | `0 * * * *` | Runs at minute 0 of every hour |
| Daily at midnight | `0 0 * * *` | Runs once per day at 00:00 |
| Daily at 2am | `0 2 * * *` | Runs once per day at 02:00 |
| Weekdays at 9am | `0 9 * * 1-5` | Mon–Fri at 09:00 |
| Weekly on Sunday | `0 0 * * 0` | Every Sunday at 00:00 |
| Monthly (1st) | `0 0 1 * *` | First day of each month at 00:00 |
| Every 15 minutes | `*/15 * * * *` | Runs 4 times per hour |

## Timezone

Schedules run in **UTC**. There is no per-task timezone setting; convert your local time to UTC.

## Overlapping runs

If a previous run is still active when the next tick arrives, the new run is **skipped**. Runs of one task never overlap.

## Run now

On the scheduled tasks' **Runs** list, click **Trigger Run** to start one run right away, for example to test a new task. Manual runs are marked `manual`. The API is `POST /api/apps/{pipeline}/{phase}/{app}/cronjobs/{name}/trigger`.

## Examples

### Daily report (Node.js)

```javascript title="report.js"
import pg from 'pg'
import { Resend } from 'resend'

const db = new pg.Client({ connectionString: process.env.DATABASE_URL })
const resend = new Resend(process.env.RESEND_API_KEY)

async function main() {
  await db.connect()

  const { rows } = await db.query(`
    SELECT COUNT(*) AS signups
    FROM users
    WHERE created_at >= NOW() - INTERVAL '24 hours'
  `)

  const signups = rows[0].signups

  await resend.emails.send({
    from: 'reports@acme.com',
    to: 'team@acme.com',
    subject: `Daily report: ${signups} new signups`,
    text: `You had ${signups} new users sign up in the last 24 hours.`,
  })

  console.log('Report sent successfully.')
  await db.end()
}

main().catch((err) => {
  console.error('Report failed:', err)
  process.exit(1)   // Non-zero exit marks run as failed
})
```

Schedule: `0 8 * * *`, runs daily at 08:00 UTC.

### Queue sweep (Python)

```python title="sweep.py"
"""
Cleans up stale jobs that have been stuck in 'processing' state for > 1 hour.
Schedule: */30 * * * *  (every 30 minutes)
"""
import os
import redis
import time

r = redis.from_url(os.environ['REDIS_URL'])

now = time.time()
stale_cutoff = now - 3600  # 1 hour

stuck = r.zrangebyscore('jobs:processing', '-inf', stale_cutoff)
if stuck:
    print(f"Requeueing {len(stuck)} stale jobs")
    pipe = r.pipeline()
    for job_id in stuck:
        pipe.zrem('jobs:processing', job_id)
        pipe.rpush('jobs:pending', job_id)
    pipe.execute()
else:
    print("No stale jobs found")

print("Sweep complete.")
```

### Cache warmup

```javascript title="warmup.js"
/**
 * Pre-populates Redis with frequently-accessed data before business hours.
 * Schedule: 0 7 * * 1-5  (Weekdays at 07:00 UTC)
 */
import { createClient } from 'redis'
import db from './db.js'

const redis = createClient({ url: process.env.REDIS_URL })
await redis.connect()

const products = await db.query('SELECT * FROM products WHERE active = true')
await redis.set('cache:active-products', JSON.stringify(products.rows), { EX: 86400 })

const categories = await db.query('SELECT * FROM categories')
await redis.set('cache:categories', JSON.stringify(categories.rows), { EX: 86400 })

console.log(`Cache warmed: ${products.rows.length} products, ${categories.rows.length} categories`)
await redis.quit()
```

## Viewing run history

The **Runs** list shows scheduled, manual, and after-deploy runs with their state and start time. Click a run to open its logs. A schedule-only service shows its runs on the **Runs** tab (in place of **Deployment**).

## Related

For tasks that need to react to events rather than run on a schedule, use a [Background Worker](/deploy/background-workers/) instead. For triggering deploys from external systems, see [Deploy Hooks](/cicd/deploy-hooks/).
