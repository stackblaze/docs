A **service** is a container StackBlaze builds and runs. Add one from the canvas with **+ Service**. Source is a Git repository, a Docker image, or a template. Databases are services on the same board.

Web, worker, and cron are **settings** on a service (public domain, no domain, or a schedule) — not separate products.

<Diagram file="service-types.svg" alt="Five service types on one project canvas: Web with public HTTPS, Worker with no ingress, Cron on a schedule, and Postgres and Redis add-ons on a private network" />

## Types of services

### Always-on

The default. The container stays running. Use this for HTTP APIs, frontends, queue consumers, and anything that must not exit.

- Give it a public domain for HTTP → [Public HTTP](/deploy/web-services/)
- Leave it private for workers → [Private services](/deploy/background-workers/)

### Scheduled

A [cron job](/deploy/cron-jobs/) runs until completion on a cron expression, then exits. Same build path as always-on services.

### Functions

A [function](/functions/) is one TypeScript file run on Bun, with no build. It sleeps when idle, or runs on a schedule.

### Databases

From **+ Service → Database or cache**, provision PostgreSQL, MariaDB, Valkey, and other managed engines. They join the environment's [private network](/networking/private-networking/). Wire connection strings with [variables](/security/env-vars/) (`fromDatabase` in config as code).

## Create a service

<Steps>

1. Open a project. You are on the environment canvas (production unless you switched).

2. Click **+ Service** and pick a source:

   - **Template** — one-click apps from the catalog
   - **GitHub repository** — build and deploy from a repo
   - **Docker image** — run a public or private image
   - **Database or cache** — managed engine
   - **Function** — one TypeScript file, no build (when Functions is on for your plan)
   - **Import** — Compose, `render.yaml`, or `fly.toml`

3. Click **Commit N changes** in the toolbar, review the [staged changes](/deploy/staged-changes/), and click **Deploy N changes**.

</Steps>

## Service source

If a `Dockerfile` is in the repo, StackBlaze proposes it (build method **Docker**). Otherwise it builds with **Railpack**, which detects the runtime from files such as `package.json` or `requirements.txt`. **Buildpacks** is also available. Pick the **Build method** in the service **Settings**.

In **Settings → Deploy** you can set a **Build command** and **Start command** (blank uses the framework default) and a **Pre-deploy** command, such as `npm run migrate`, that runs before each deploy goes live. If the pre-deploy command fails, the deploy stops and the current version keeps running.

Change source later from the service **Settings** tab.

## Monorepos
