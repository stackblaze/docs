title: ASP.NET Core
description: Deploy ASP.NET Core on StackBlaze from GitHub or a Dockerfile.

Add a service from your ASP.NET Core repo. Railpack detects **dotnet** from `*.csproj`. If the service root has a `Dockerfile`, StackBlaze builds from it instead.

Railpack publishes the project and starts it with `ASPNETCORE_URLS=http://0.0.0.0:$PORT`. A `Dockerfile` FROM `mcr.microsoft.com/dotnet/aspnet` also works; listen on `http://+:$PORT`.

## Deploy from GitHub

1. [Dashboard](https://dashboard.stackblaze.cloud) → **New Project** (or open an existing canvas).
2. **+ Service → GitHub repository**. Pick the repo and branch.
3. Click **Commit 1 change**, review the [staged changes](/deploy/staged-changes/), and **Deploy**.
4. A service exposed to the internet gets a `*.stackblaze.app` URL. Attach a [custom domain](/networking/custom-domains/) if you want your own.

StackBlaze sets `PORT` to the service port. Set the port on the service to match your app. If detection is wrong, change **Build method**, **Build command**, or **Start command** on the service. Typical start: with a Dockerfile, `dotnet MyApp.dll`.

## Docker

If you already have a `Dockerfile`, StackBlaze uses it. The process must listen on `PORT`.

## Data

**+ Service → Database or cache** for PostgreSQL, MariaDB, Valkey, and more. Wire `DATABASE_URL` from the service **Variables** tab or `fromDatabase` in [stackblaze.yaml](/blueprint/).

## CLI

```bash
stackblaze login
stackblaze init
stackblaze up
```

See the [CLI](/cli/).
