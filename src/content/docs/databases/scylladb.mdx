Managed ScyllaDB (2025.1.5), a Cassandra-compatible wide-column database, run by the Scylla operator.

## Creating a ScyllaDB database

From **+ Service → Databases**, add **ScyllaDB**. It appears on the canvas as a staged change. Apply your staged changes and StackBlaze creates it with the catalog defaults: one node with a 10 GB volume.

To connect a service, open the database, go to **Settings → Connection**, and switch the service on.

ScyllaDB is Cassandra-compatible: it is a C++ rewrite of Apache Cassandra. Because of this, existing Cassandra drivers and your existing CQL (Cassandra Query Language) work against it without changes.

## Connecting

ScyllaDB uses the CQL binary protocol on port `9042`, the same wire protocol as Cassandra. Any Cassandra-compatible driver can talk to it directly. A connected service gets `SCYLLA_HOST` and `SCYLLA_PORT`, plus the same values as `CQL_HOST` / `CQL_PORT` and `CASSANDRA_HOST` / `CASSANDRA_PORT`. Services in the same environment reach it over the private network:

```text title="Contact point (internal)"
[service-name]:9042
```

## Topology

A new ScyllaDB database is a single node. ScyllaDB has no **Enable HA** switch in the dashboard. With one node, use a replication factor of 1 for your keyspaces.

## Connecting from Python

The standard `cassandra-driver` package works with ScyllaDB. Read the host and port from the environment, connect, and run a CQL query:

```python title="app.py"
import os
from cassandra.cluster import Cluster

cluster = Cluster(
    [os.environ["SCYLLA_HOST"]],
    port=int(os.environ["SCYLLA_PORT"]),
)
session = cluster.connect()

rows = session.execute("SELECT release_version FROM system.local")
for row in rows:
    print(row.release_version)

cluster.shutdown()
```

## Backups

Backups are off until you turn on a schedule for the environment. Recovery points hold a copy of the database's volumes. A restore always creates a new database next to the running one. See [Backups & recovery](/databases/backups/).
