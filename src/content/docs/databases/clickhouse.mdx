Managed ClickHouse, a fast columnar OLAP database, run by the Altinity ClickHouse operator. New databases get the ClickHouse 26.8 LTS release.

:::note
ClickHouse is off until a platform admin turns it on. If you do not see it under **+ Service → Databases**, it is not available on your platform yet.
:::

## Creating a ClickHouse database

From **+ Service → Databases**, add **ClickHouse**. It appears on the canvas as a staged change. Apply your staged changes and StackBlaze creates it with the catalog defaults: one replica with an 8 GB data volume, a user `app`, and a database `app`.

To connect a service, open the database, go to **Settings → Connection**, and switch the service on.

## Connection variables

ClickHouse exposes an HTTP interface on port `8123` and the native TCP protocol on port `9000`.

| Variable | Value |
| --- | --- |
| `CLICKHOUSE_HOST` | Internal hostname |
| `CLICKHOUSE_PORT`, `CLICKHOUSE_NATIVE_PORT` | `9000` |
| `CLICKHOUSE_HTTP_PORT` | `8123` |
| `CLICKHOUSE_URL` | `http://[host]:8123` (no credentials in it) |
| `CLICKHOUSE_NATIVE_URL` | `clickhouse://[host]:9000/app` |
| `CLICKHOUSE_DATABASE`, `CLICKHOUSE_DB` | `app` |
| `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD` | From a secret |

**Settings → Access** shows the connection details. `stackblaze addons expose <addon>` gives the HTTP interface a public HTTPS address.

## High availability

ClickHouse high availability is two replicas plus ClickHouse Keeper. It is chosen when the database is created: there is no **Enable HA** switch for an existing ClickHouse, because its existing tables would not replicate. To make one highly available, back it up and restore the backup into a new ClickHouse created with high availability.

## Querying

The HTTP interface accepts SQL in the request body.

```bash title="Query over HTTP"
curl "$CLICKHOUSE_URL/?database=$CLICKHOUSE_DATABASE" \
  -u "$CLICKHOUSE_USER:$CLICKHOUSE_PASSWORD" \
  --data-binary "SELECT version()"
```

Use the native port `9000` with clients that speak the native protocol, such as `clickhouse-client`, for lower overhead and streaming inserts.

ClickHouse uses table engines to control how data is stored. The `MergeTree` engine is the standard choice for analytical tables.

```sql title="Create, insert, select"
CREATE TABLE events (
  id    UInt64,
  name  String,
  ts    DateTime
) ENGINE = MergeTree()
ORDER BY (ts, id);

INSERT INTO events VALUES (1, 'signup', now());

SELECT name, count() AS n
FROM events
GROUP BY name
ORDER BY n DESC;
```

:::tip
Define an explicit `ORDER BY` key on your `MergeTree` tables. It determines how data is sorted on disk and has a large effect on query performance for analytical workloads.
:::

## Backups

Backups are off until you turn on a schedule for the environment. Recovery points hold a native ClickHouse `BACKUP` archive of the database. A restore always creates a new database next to the running one. See [Backups & recovery](/databases/backups/).
