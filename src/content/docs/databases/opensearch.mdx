Managed OpenSearch for full-text search and analytics, run by the OpenSearch operator. New databases get OpenSearch 3.9.0.

:::note
OpenSearch is off until a platform admin turns it on. If you do not see it under **+ Service → Databases**, it is not available on your platform yet.
:::

## Creating an OpenSearch database

From **+ Service → Databases**, add **OpenSearch**. It appears on the canvas as a staged change. Apply your staged changes and StackBlaze creates it with the catalog defaults: one node with an 8 GB data volume.

To connect a service, open the database, go to **Settings → Connection**, and switch the service on.

## Connection variables

OpenSearch serves its REST API over HTTPS on port `9200`, with the security plugin on. The certificate is signed by the cluster's own CA.

| Variable | Value |
| --- | --- |
| `OPENSEARCH_HOST`, `OPENSEARCH_PORT` | Internal hostname, `9200` |
| `OPENSEARCH_URL` | `https://[service-name]:9200` (no credentials in it) |
| `OPENSEARCH_USERNAME`, `OPENSEARCH_PASSWORD` | Admin user, from a secret |
| `OPENSEARCH_CA_CERT` | The cluster's CA certificate, to trust in your client |
| `ELASTICSEARCH_*` | The same values under Elasticsearch names (`ELASTICSEARCH_URL`, `ELASTICSEARCH_USERNAME`, …), for clients that only know those |

The certificate names the internal hostname, so hostname verification works when your client trusts `OPENSEARCH_CA_CERT`.

## High availability

Open the database, go to **Settings → HA**, and click **Enable HA**. The cluster grows to 3 nodes. HA needs a plan with database high availability (Pro or Business) and is one-way. Give your indexes at least one replica shard so a node loss does not lose data.

## Indexing and searching

OpenSearch speaks JSON over HTTP. The example writes the CA to a file, then creates an index, indexes a document, and runs a match query.

```bash title="index-and-search.sh"
printf '%s' "$OPENSEARCH_CA_CERT" > /tmp/opensearch-ca.crt
OS="curl -s --cacert /tmp/opensearch-ca.crt -u $OPENSEARCH_USERNAME:$OPENSEARCH_PASSWORD"

# Create an index
$OS -X PUT "$OPENSEARCH_URL/articles"

# Index a document
$OS -X POST "$OPENSEARCH_URL/articles/_doc" \
  -H 'Content-Type: application/json' \
  -d '{ "title": "Hello OpenSearch", "body": "Full-text search made simple." }'

# Search the index
$OS -X GET "$OPENSEARCH_URL/articles/_search" \
  -H 'Content-Type: application/json' \
  -d '{ "query": { "match": { "title": "OpenSearch" } } }'
```

:::tip
Refreshing is near real time. If a freshly indexed document does not appear in search results immediately, allow a moment for the refresh interval, or use the `refresh` query parameter when indexing test data.
:::

## Backups

Backups are off until you turn on a schedule for the environment. Recovery points hold an OpenSearch snapshot archive of the database. A restore always creates a new database next to the running one. See [Backups & recovery](/databases/backups/).
