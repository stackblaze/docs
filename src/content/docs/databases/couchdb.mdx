Managed Apache CouchDB: a document database with an HTTP/JSON API and multi-master replication. Versions 3.2.1 (default), 3.3, and 3.4.2 are offered.

## Creating a CouchDB database

From **+ Service → Databases**, add **CouchDB**. It appears on the canvas as a staged change. Apply your staged changes and StackBlaze creates it with the catalog defaults.

To connect a service, open the database, go to **Settings → Connection**, and switch the service on.

A connected service gets `COUCHDB_HOST`, `COUCHDB_PORT` (`5984`), `COUCHDB_USER` (`admin`), and `COUCHDB_PASSWORD` (from a secret). `COUCHDB_URL` with the credentials is set only when the password is part of the database's definition.

CouchDB is a document database with an HTTP/JSON API and multi-master replication. That sync model makes it a good fit for offline-first apps, where a client database (for example PouchDB) replicates with the server and resolves changes when connectivity returns.

## Connecting

CouchDB exposes an HTTP/JSON REST API on port `5984`. Services in the same environment reach it over the private network:

```text title="Endpoint (internal)"
http://user:password@[service-name]:5984
```

Any HTTP client works: `curl`, a language HTTP library, or a CouchDB driver. Without `COUCHDB_URL`, compose it in the service's variables:

```text title="Variable"
COUCHDB_URL=http://$(COUCHDB_USER):$(COUCHDB_PASSWORD)@$(COUCHDB_HOST):$(COUCHDB_PORT)
```

## Topology

CouchDB has no **Enable HA** switch in the dashboard. The node count is set when the database is created.

## Working with documents

CouchDB is driven entirely over HTTP. Create a database with `PUT`, add a document with `POST`, and read it back with `GET`, all against `COUCHDB_URL`:

```bash title="documents.sh"
# Create a database named "app"
curl -X PUT "$COUCHDB_URL/app"

# Create a document in that database
curl -X POST "$COUCHDB_URL/app" \
  -H "Content-Type: application/json" \
  -d '{"_id": "user:1", "name": "Ada"}'

# Read the document back
curl "$COUCHDB_URL/app/user:1"
```

## Backups

Backups are off until you turn on a schedule for the environment. Recovery points hold a copy of the database's volumes. A restore always creates a new database next to the running one. See [Backups & recovery](/databases/backups/).
