Two catalog entries speak the Redis protocol:

| Entry | Engine | Versions | Topology | Auth |
| --- | --- | --- | --- | --- |
| **Valkey** | Valkey operator | 8.0 (default), 7.2 | One instance, master/replica HA available | None (private network only) |
| **Redis** | Official `redis` image | 8.10 (default), 8.8, 8.6, 8.4, 8.2 | One instance | Password |

Valkey is the open-source, Redis-compatible fork. Redis clients and commands work unchanged. The official Redis entry is off until a platform admin turns it on, so you may only see Valkey.

## Creating an instance

From **+ Service → Databases**, add **Valkey** (or **Redis**). It appears on the canvas as a staged change. Apply your staged changes and StackBlaze creates it with the catalog defaults.

To connect a service, open the instance, go to **Settings → Connection**, and switch the service on.

## Connection variables

| Variable | Valkey | Redis |
| --- | --- | --- |
| `REDISHOST`, `REDISPORT` | Internal hostname, `6379` | Internal hostname, `6379` |
| `REDIS_URL` | `redis://[service-name]:6379` | Full URL with the password, from a secret |
| `REDIS_HOST`, `REDIS_PORT` | Not set | Set |
| `REDISUSER` | Not set | `default` |
| `REDISPASSWORD`, `REDIS_PASSWORD` | Not set | From a secret |

```text title="Valkey (internal)"
redis://[service-name]:6379
```

```text title="Redis (internal)"
redis://default:password@[service-name]:6379
```

Valkey runs without a password and is reachable only from the environment's private network. Because it has no password, it cannot be given public access. The official Redis image has a password and can be exposed under **Settings → Access → Public access**, only from the IP addresses you allow.

From your machine, `stackblaze connect redis` opens `redis-cli`. Add `--tunnel` to keep a local port open for GUI tools.

## Memory and connections

Your plan sets the memory limit and the maximum number of clients. See **Settings → Plan limits**. The official Redis image runs with `noeviction`: when memory is full, writes fail and nothing is dropped. Set TTLs on cache keys so the data set does not grow without bound.

## Common use cases

### Caching (Node.js / ioredis)

```ts title="cache.ts"
import Redis from 'ioredis'

const redis = new Redis(process.env.REDIS_URL)

async function getUser(id: string) {
  const cached = await redis.get(`user:${id}`)
  if (cached) return JSON.parse(cached)

  const user = await db.users.findById(id)
  await redis.setex(`user:${id}`, 3600, JSON.stringify(user)) // TTL: 1 hour
  return user
}
```

### Session storage (Express + connect-redis)

```ts title="server.ts"
import session from 'express-session'
import { createClient } from 'redis'
import { RedisStore } from 'connect-redis'

const client = createClient({ url: process.env.REDIS_URL })
await client.connect()

app.use(session({
  store: new RedisStore({ client }),
  secret: process.env.SESSION_SECRET,
  resave: false,
  saveUninitialized: false,
  cookie: { secure: true, maxAge: 86400000 }, // 24 hours
}))
```

### Job queues with BullMQ

```ts title="queue.ts"
import { Queue, Worker } from 'bullmq'

const connection = { url: process.env.REDIS_URL }

// Producer: add jobs from your API
const emailQueue = new Queue('emails', { connection })

export async function sendWelcomeEmail(userId: string) {
  await emailQueue.add('welcome', { userId }, {
    attempts: 3,
    backoff: { type: 'exponential', delay: 2000 },
  })
}

// Consumer: process jobs in a worker service
const worker = new Worker('emails', async (job) => {
  const { userId } = job.data
  await mailer.sendWelcome(userId)
}, { connection })
```

### Pub/Sub (broadcasting across instances)

When a service runs several instances, use pub/sub to broadcast events to all of them, for example from WebSocket servers.

```ts title="pubsub.ts"
import { createClient } from 'redis'

const publisher = createClient({ url: process.env.REDIS_URL })
const subscriber = publisher.duplicate()

await publisher.connect()
await subscriber.connect()

// Publish from any instance
await publisher.publish('notifications', JSON.stringify({ userId, message }))

// Subscribe on every instance
await subscriber.subscribe('notifications', (message) => {
  const { userId, message: msg } = JSON.parse(message)
  io.to(userId).emit('notification', msg) // Socket.IO broadcast
})
```

## High availability (Valkey)

Open the Valkey instance, go to **Settings → HA**, and click **Enable HA**. StackBlaze adds a replica (master / replica). HA needs a plan with database high availability (Pro or Business) and is one-way. The official Redis image has no HA.

## Backups

Backups are off until you turn on a schedule for the environment. Recovery points hold a dump of an official Redis instance and a copy of a Valkey instance's volume. A restore always creates a new instance next to the running one. See [Backups & recovery](/databases/backups/).
