Two catalog entries speak the MySQL protocol:

| Entry | Engine | Versions | Topology |
| --- | --- | --- | --- |
| **MariaDB** | MariaDB operator | 11.4 (default), 11.2, 10.11 | One instance, Galera HA available |
| **MySQL** | Official `mysql` image | 8.4 (default), 9.7 | One instance |

MySQL drivers, ORMs, and SQL work against both. The official MySQL entry is off until a platform admin turns it on, so you may only see MariaDB.

## Creating a database

From **+ Service → Databases**, add **MariaDB** (or **MySQL**). It appears on the canvas as a staged change. Apply your staged changes and StackBlaze creates it with the catalog defaults: a database named `app` on a 1 GB volume.

To connect a service, open the database, go to **Settings → Connection**, and switch the service on.

## Connection variables

| Variable | MariaDB | MySQL |
| --- | --- | --- |
| `MYSQL_HOST` | Internal hostname | Internal hostname |
| `MYSQL_PORT` | `3306` | `3306` |
| `MYSQL_USER` | The database user | `app` |
| `MYSQL_PASSWORD` | From a secret | From a secret |
| `MYSQL_DATABASE` | `app` | `app` |
| `MYSQL_URL`, `DATABASE_URL` | Not set | `mysql://…` from a secret |

For MariaDB, compose a URL in the service's variables if your app needs one:

```text title="Variable"
DATABASE_URL=mysql://$(MYSQL_USER):$(MYSQL_PASSWORD)@$(MYSQL_HOST):$(MYSQL_PORT)/$(MYSQL_DATABASE)
```

### Internal

Services in the same environment reach the database over the private network. **Settings → Access** shows the host, user, password, connection URL, JDBC URL, and an environment snippet.

```text title="Connection string (internal)"
mysql://user:password@[service-name]:3306/app
```

### From your machine

- `stackblaze connect mysql` opens a `mysql` shell. Add `--local` or `--tunnel` to go through a private tunnel to your machine for MySQL Workbench, TablePlus, or DBeaver.
- **Settings → Access → Public access** makes the database reachable from outside the platform, only from the IP addresses you allow. TLS is required. The CLI equivalent is `stackblaze addons expose <addon> --allow <ip/cidr>`.

## ProxySQL

**ProxySQL** (under **+ Service → Add-ons**) adds connection pooling and read/write splitting in front of MariaDB. Point it at your MariaDB service and connect your app to ProxySQL instead. Connected services get `MYSQL_HOST`, `MYSQL_PORT` (`6033`), `MYSQL_USER`, `MYSQL_PASSWORD`, the same values as `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_USER`, `DATABASE_PASSWORD`, and `PROXYSQL_HOST` / `PROXYSQL_PORT`. Its **Settings** show **Backends** and **Read/Write Split**.

## Running migrations

Set a pre-deploy command under **Settings → Deploy → Pre-deploy** so migrations finish before the new version starts. If it fails, the current version stays live.

### Prisma

```bash title="Pre-deploy command"
npx prisma migrate deploy
```

### Flyway

```bash title="Pre-deploy command"
flyway -url=jdbc:mysql://$MYSQL_HOST:$MYSQL_PORT/$MYSQL_DATABASE \
        -user=$MYSQL_USER \
        -password=$MYSQL_PASSWORD \
        migrate
```

### Node.js / Knex

```bash title="Pre-deploy command"
npx knex migrate:latest
```

To load an existing dump, use `stackblaze addons import <file> [addon]` (plain SQL from `mysqldump` or `mariadb-dump`, also gzipped).

## High availability (MariaDB)

Open the MariaDB database, go to **Settings → HA**, and click **Enable HA**. StackBlaze creates a new 3-node Galera cluster from a backup, moves your services to it, and keeps the old instance for rollback. When it finishes, open the new cluster from the HA section. HA needs a plan with database high availability (Pro or Business) and is one-way.

The official MySQL entry has no HA.

## Backups

Backups are off until you turn on a schedule for the environment. Recovery points hold a dump of each MariaDB and MySQL database, and a restore always creates a new database next to the running one. See [Backups & recovery](/databases/backups/).

MariaDB runs with row-based binary logging, so the Kafka MySQL/MariaDB CDC connector works against it without extra setup.

## Character sets

Check the server's character set and collation before you create tables, and set `utf8mb4` explicitly if your app needs full Unicode:

```sql title="Check charset"
SHOW VARIABLES LIKE 'character_set%';
SHOW VARIABLES LIKE 'collation%';
```

## Connecting with common ORMs

### Prisma (MySQL provider)

```prisma title="prisma/schema.prisma"
datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}
```

### TypeORM

```ts title="data-source.ts"
import { DataSource } from 'typeorm'

export const AppDataSource = new DataSource({
  type: 'mysql',
  host: process.env.MYSQL_HOST,
  port: Number(process.env.MYSQL_PORT),
  username: process.env.MYSQL_USER,
  password: process.env.MYSQL_PASSWORD,
  database: process.env.MYSQL_DATABASE,
  entities: ['src/entities/**/*.ts'],
  migrations: ['src/migrations/**/*.ts'],
})
```

### SQLAlchemy (Python)

```python title="database.py"
import os
from sqlalchemy import create_engine
from sqlalchemy.engine import URL

url = URL.create(
    "mysql+pymysql",
    username=os.environ["MYSQL_USER"],
    password=os.environ["MYSQL_PASSWORD"],
    host=os.environ["MYSQL_HOST"],
    port=int(os.environ["MYSQL_PORT"]),
    database=os.environ["MYSQL_DATABASE"],
)
engine = create_engine(url, pool_pre_ping=True)
```
