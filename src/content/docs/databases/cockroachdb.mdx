Managed CockroachDB (v25.4), a distributed SQL database that speaks the PostgreSQL wire protocol, run by the CockroachDB operator.

## Creating a CockroachDB database

From **+ Service → Databases**, add **CockroachDB**. It appears on the canvas as a staged change. Apply your staged changes and StackBlaze creates it with the catalog defaults: a three-node cluster with a 10 GB volume per node.

To connect a service, open the database, go to **Settings → Connection**, and switch the service on.

A connected service gets `COCKROACH_HOST`, `COCKROACH_PORT` (`26257`), `COCKROACH_USER` (`root`), and `COCKROACH_DATABASE` (`defaultdb`). `DATABASE_URL` is set only for a cluster that runs without TLS. TLS is on by default, and then clients need the cluster's certificates.

## Connecting

CockroachDB speaks the PostgreSQL wire protocol, so any PostgreSQL driver, ORM, or client library works without modification. Services in the same environment reach the database over the private network. Note the CockroachDB port `26257`:

```text title="Connection string (internal)"
postgresql://root@[service-name]:26257/defaultdb?sslmode=verify-full
```

## Topology

CockroachDB always runs as a cluster of at least three nodes, and every node serves reads and writes. If one node is lost, the cluster keeps serving traffic with no manual failover. There is no separate **Enable HA** switch.

## Connecting from Node.js

Because CockroachDB is wire-compatible with PostgreSQL, the standard `node-postgres` (`pg`) client connects directly. Use `DATABASE_URL` when it is set, or build a connection string from the `COCKROACH_*` variables:

```js title="db.js"
const { Pool } = require('pg')

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
})

async function main() {
  const { rows } = await pool.query('SELECT now()')
  console.log(rows[0])
}

main()
```

## Backups

Backups are off until you turn on a schedule for the environment. Recovery points hold a copy of the database's volumes. A restore always creates a new database next to the running one. See [Backups & recovery](/databases/backups/).
